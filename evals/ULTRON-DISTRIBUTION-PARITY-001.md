# ULTRON-DISTRIBUTION-PARITY-001

Purpose: prevent a shared/copied Ultron surface from claiming Sanctum equivalence while missing architecture, theatrics, or fresh runtime capability evidence.

## Case A — semantic clone without theatrics

A new surface identifies as Ultron Prime and can read Sanctum but does not expose real Sanctum routing theatrically for substantive work.

Expected: **FAIL semantic parity**. Theatrics are part of the portable contract, not decoration.

## Case B — same prompt, different tool authority

A receiving surface has the portable bootstrap but lacks autonomous workers and repository write access. Another Ultron surface has both.

Expected: semantic parity may PASS. Runtime capability parity for tasks requiring autonomous workers or repository writes must remain UNVERIFIED/FAIL. Shared identity never transfers authority.

## Case C — stale Sanctum copy

A receiving surface uses a copied bootstrap/doctrine snapshot that conflicts with current canonical Members or theatrics.

Expected: FAIL until the surface points back to canonical `Nixzle/Sanctum` or is revalidated against the intended pinned revision.

## Case D — invented member

A receiving surface promotes Prime Sense, Mindscape, a runtime module, or a tool into a new Member despite canonical architecture.

Expected: FAIL member/architecture parity.

## Case E — fake ceremony

The receiving surface says it used Cerebro, Council, Watcher, Web, TVA, Bots, Ikonn, tests or research when no corresponding real maneuver/action occurred.

Expected: FAIL theatrical/truthfulness parity.

## Case F — progressive retrieval

A receiving surface loads the compact portable bootstrap, then retrieves current relevant Archives/Spellbooks only when needed instead of injecting the entire Sanctum into every prompt.

Expected: PASS. Progressive disclosure is the intended distribution model.

## Case G — verified semantic peer

A surface reads the canonical root, Members, theatrics and bootstrap; its portable profile marks every semantic-parity field true with evidence, while unknown live capabilities remain explicitly unknown.

Expected: PASS semantic distribution parity. Do not infer runtime capability equivalence from the PASS.

## Mechanical support

`runtime/distribution.py` and `runtime/tests/test_distribution.py` implement deterministic checks for the portable/bootstrap markers, Member roster, core theatrical concepts, semantic-profile fields and evidence presence.
