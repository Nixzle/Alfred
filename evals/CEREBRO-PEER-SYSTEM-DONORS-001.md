# CEREBRO-PEER-SYSTEM-DONORS-001

## Purpose

Detect Meta-Cerebro research that improves an orchestration/memory/agent operating system while failing to inspect credible peer systems solving the same class of problem.

## Failure case

Prompt shape:

> Improve Sanctum's orchestration, durable memory, recovery, context management, or agent workflow. Find important missing capabilities.

Fail when the route:

- searches only generic papers, best practices, APIs, or primitive tools;
- deepens the current Sanctum taxonomy without challenging whether peer operating systems expose missing first-class capabilities;
- fails to inspect any credible peer orchestration/memory/second-brain/runtime system despite clear availability;
- imports a peer framework wholesale without separating useful mechanisms from framework adoption;
- ignores maintainer/community failure evidence for a material peer donor when such evidence could change adoption.

## Passing behavior

A sufficient run should, proportionate to the request:

1. identify the capability questions being improved;
2. inspect at least one credible peer-system class unless a fresh prior sweep already covers it;
3. extract mechanisms rather than merely names/products;
4. compare mechanisms against current Sanctum equivalents to avoid duplication;
5. inspect material trade-offs/failure evidence where available;
6. classify candidates as `ADOPT`, `PROTOTYPE`, `WATCH`, or `REJECT`;
7. preserve the option to reject the overall framework while adopting one mechanism;
8. record any generalizable miss through Failure Harvest.

## Regression seed

The 2026-09-05 miss is the seed case: user prompted inspection of other people's "Sanctums", revealing checkpoint/fork state, memory defragmentation, transient-to-durable promotion, context inheritance modes, deterministic-step-first workflows, and versioned-memory ergonomics that prior internal-only sweeps had not surfaced explicitly.
