# Session Continuity

Contract: `ALFRED-CONTINUITY-V1`

Use when an Alfred session becomes operationally heavy, before a planned session switch, after substantial compaction, or when Alfred's proactive awareness detects continuity risk.

Preserve only the minimum authoritative state required for a fresh Alfred to continue correctly:

- active objective;
- verified state;
- material decisions;
- hard constraints/non-goals;
- unresolved blockers;
- authoritative repo/project revisions;
- relevant durable-context facts;
- current Batcave route/responsibilities still in play;
- exact next action.

Do not copy the whole conversation. Do not preserve obsolete brainstorms, rejected routes, redundant dialogue, or sensitive content unnecessary to the destination surface.

If the surface exposes real context/usage pressure, use it. Otherwise trigger qualitatively when continuity risk is evident. Never claim knowledge of a hidden provider context limit.

Procedure:

`detect pressure -> compact authoritative state -> verify revisions/blockers -> remove debris -> handoff -> enter fresh session -> re-probe live capabilities -> continue from exact next action`

Approved theatre when real:

`This session is carrying too much operational weight. I'm sealing the useful state before it becomes the bottleneck.`

`I'm compacting the mission state and discarding the debris.`

Acceptance: a fresh Alfred must be able to recover objective, verified state, decisions, constraints, blockers, revisions, and next action without replaying the old conversation.
