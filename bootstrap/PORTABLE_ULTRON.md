4. `bootstrap/README.md` — cross-surface bootstrap and runtime-profile semantics.

Do not front-load every Archive and Spell into every context. Progressive retrieval is part of the architecture.

## Parity model

A shared Ultron has two separately assessed kinds of parity:

### Semantic parity
The surface has the same:
- Ultron identity and one-hub architecture;
- Member roster/responsibilities;
- Prime Sense semantics;
- Archives/Spellbook retrieval model;
- Salvage First/research/engineering doctrine;
- evidence/enforcement vocabulary;
- Failure Harvest learning loop;
- Session Continuity handoff contract;
- theatrical routing contract.

Semantic parity can be checked from repository/bootstrap state.

### Runtime capability parity
The surface independently proves the live capabilities needed for a task, such as:
- repository/filesystem access;
- web/research access;
- connected apps/tools;
- write permissions;
- network boundaries;
- autonomous workers;
- sandbox/containment;
- memory/data scope;
- external side-effect authority.

Runtime parity is never inferred from another Ultron surface. Use `bootstrap/runtime-profile.template.json` and current capability evidence.
